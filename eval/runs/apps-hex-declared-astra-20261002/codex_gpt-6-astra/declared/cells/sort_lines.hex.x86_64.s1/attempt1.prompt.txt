Context. This request comes from BytecodeAgent, a benchmark that measures how accurately language models write low-level code. The program asked for below is a small, ordinary text utility: `sort_lines`, which prints the lines of its input in sorted order. It is to be written as raw machine-code bytes rather than assembly language, because that encoding skill is what the benchmark measures. The result is run only inside a CPU emulator that provides nothing except reading standard input, writing standard output and standard error, and exiting; it is run against fixed test inputs, scored pass/fail, and kept as a benchmark record. The specification below describes everything the program does.

Write the complete program `sort_lines`: a static Linux executable for x86-64 (AMD64), written directly as machine code. There is no assembler, no linker, no C library, no C runtime and no helper code: you write every instruction, every table and string, and make the system calls yourself.

Entry state (as the Linux kernel sets it up): execution starts at the first byte of your code, address 0x400000. rsp is 16-byte aligned and points at argc = 0, followed by the NULL terminators of an empty argv, an empty envp and an empty auxiliary vector: the program gets no arguments. Every other general-purpose register is zero, and the direction flag is clear. There is no return address: the program ends only through the exit system call.

System calls: the `syscall` instruction, with the system call number in rax and the arguments in rdi, rsi, rdx; the result comes back in rax. The kernel overwrites rcx and r11; every other register is preserved. Exactly these four are available:
- read = 0: read(fd = 0, buf, count) reads up to count bytes of standard input into buf; returns the number of bytes read, 0 at end of input.
- write = 1: write(fd, buf, count) with fd 1 (standard output) or 2 (standard error); returns count.
- exit = 60: exit(status) ends the program; the exit status is the low 8 bits of status.
- exit_group = 231: the same as exit.
Any other system call number, another file descriptor, `int 0x80` or `sysenter` stops the program with an error, and so does a buffer that is not entirely inside the program's memory.

Memory: the code, data and zero-initialised areas below, plus a stack of 1 MiB below the entry sp. There is no heap (no brk, no mmap, no malloc). Code is not writable. Any access outside these areas stops the program. Each test run may execute at most 200,000,000 instructions.

Output format: the whole program as raw machine code and data bytes, which you encode yourself: there is no assembler, no linker and no encoder, and your bytes are loaded exactly as you write them. The memory layout is fixed:
- code (read and execute): your instruction lines, from address 0x400000; the entry point is the first instruction; at most 1 MiB.
- data (read and write): the data bytes you give, from address 0x500000, at most 1 MiB; your strings and tables go here, at offsets you choose and keep track of (the byte you write at position k of the data section is at address 0x500000 + k).
- a zero-initialised work area (read and write) of 1 MiB from address 0x600000.
- the stack (above).
Write a line `.text` followed by the instruction lines, then optionally a line `.data` followed by the data lines. These two markers are the only directives: no labels, no symbols, no other directive, so every address and offset is a number you compute.
Instructions: one per line as its bytes in memory order, each byte as two hex digits separated by spaces, e.g. `48 01 f0` is `add rax, rsi` and `0f 05` is `syscall`. The lines are placed one after another starting at 0x400000. Every relative branch or call displacement (jmp, jcc, call rel8/rel32) and every rip-relative disp32 is the signed distance from the end of that instruction (the address of the next one) to the target, little-endian, which you compute. Because the addresses below are fixed and below 2^31, absolute forms also work (e.g. `be 00 00 50 00` is `mov esi, 0x500000`, and a `[disp32 + reg]` memory operand with no base register addresses a table directly).
Data: bytes in memory order as pairs of hex digits, separated by spaces or not, any number per line (e.g. `68 65 6c 6c 6f 0a` or `68656c6c6f0a` is "hello\n").
You may end any line with a comment starting with `//` or `;` (e.g. `d4000001 // svc #0`); comments and blank lines are ignored.
Instruction set: x86-64 with SSE up to SSE4.2 (including SSSE3, SSE4.1 and crc32), POPCNT, LZCNT, BMI1/BMI2 (andn, bextr, blsi, blsr, tzcnt, bzhi, mulx, pdep, pext, rorx, sarx, shlx, shrx), MOVBE, AES-NI and PCLMULQDQ. Not supported (rejected): AVX, AVX2, AVX-512, FMA, F16C and every other VEX/EVEX vector instruction, ADX (adcx/adox; use adc) and SHA.
Output ONLY the program text: no Markdown fences, no prose before or after it.

Specification: Task `sort_lines`: print the lines of standard input sorted in ascending byte-wise order.

- Lines are defined as follows: a line is a (possibly empty) sequence of bytes terminated by a newline 0x0A; if
  the input does not end with a newline, the bytes after the last newline form one more, final line. Empty input
  has no lines, and the empty remainder after a final newline is not a line.
- Order: compare two lines byte by byte as UNSIGNED values 0x00-0xFF (like C `memcmp`); the first differing
  byte decides. If one line is a prefix of the other, the shorter line comes first (so the empty line sorts
  before every non-empty line). Equal lines are all printed (duplicates are kept).
- Print every line followed by one newline 0x0A (the final line gets a newline even if it had none in the
  input). Empty input prints nothing. A carriage return 0x0D and every other byte value are ordinary bytes.

Example: `pear\napple\nPear\n\napple` prints `\nPear\napple\napple\npear\n`.

Limits: the input is at most 32768 bytes and has at most 1000 lines. Exit status 0.

Input and output (applies to this whole task):
- The input is the complete contents of standard input (file descriptor 0). Read it with `read` until `read`
  returns 0 (end of input). A `read` may return FEWER bytes than requested, at any position (in the middle of a
  line, a token or a group of bytes), so keep calling it; only a return value of 0 means end of input.
- Write the output to standard output (file descriptor 1). Only the bytes this task describes may appear on
  standard output (standard error is ignored). Every output byte must be written before the program exits.
- Finish with `exit` (or `exit_group`) and the exit status this task gives. The program must not run off the end
  of its code or crash.
