Implement the function `int64_t dot_i32_simd(const int32_t *a, const int32_t *b, int64_t n)`.

Target: AArch64 (ARMv8-A), Linux AAPCS64. Integer/pointer arguments in x0-x7; 64-bit result in x0. Callee-saved: x19-x28, x29 (frame pointer) and d8-d15 (restore them if you use them); x9-x15 are free scratch registers. sp must stay 16-byte aligned and be back to its entry value when you return with ret (return address in x30). More ABI facts: arguments beyond the eighth are passed on the stack (the 9th at [sp] at entry). A call (bl/blr) overwrites x30, so save x30 (e.g. stp x29, x30, [sp, #-16]!) before calling and restore it before ret. A call clobbers the caller-saved registers x0-x18, x30, v0-v7 and v16-v31 (and the upper halves of v8-v15) and the flags, so keep values that must survive a call in callee-saved registers x19-x28 (saved/restored by you) or in your own stack frame. sp must be 16-byte aligned at every call (and whenever it is used as a base register). Anything below sp may be overwritten by a callee.

Output format: GNU assembler syntax for AArch64, e.g. `ldr x2, [x0, x1, lsl #3]`. Output ONLY the function's instructions and labels, one per line, starting with the label `dot_i32_simd:` (the entry point). Labels are `name:` (letters, digits, _ and ., e.g. `.Lloop:`); every branch target (b, b.cond, cbz, cbnz, tbz, tbnz, bl, adr) must be a label, never a number. Comments start with `//`; do not use `;`. No directives of any kind (no .section/.align/.word/.quad), no literal pools (`ldr x0, =...`), no data, no calls to other functions. Each line under 120 characters. No Markdown fences, no prose before or after the code.

Specification: a and b each point to n signed 32-bit integers (0 <= n <= 1000; n need not be a multiple of 4 or 8). Return the sum over i of (int64_t)a[i] * (int64_t)b[i], with wrapping 64-bit arithmetic for the sum. a and b are only 4-byte aligned (not 16). The implementation MUST use SIMD vector arithmetic in its main loop (x86-64: SSE2/SSSE3/SSE4.1 on xmm registers, e.g. pmovsxdq/pmuldq/paddq; AArch64: NEON on v registers, e.g. smull/smlal), several elements per iteration, plus a scalar loop for the remaining elements; the machine code is checked for vector arithmetic instructions. No AVX. Do not read outside a[0..n-1] and b[0..n-1] (not even with a vector load that runs past the end) and do not write to memory.
