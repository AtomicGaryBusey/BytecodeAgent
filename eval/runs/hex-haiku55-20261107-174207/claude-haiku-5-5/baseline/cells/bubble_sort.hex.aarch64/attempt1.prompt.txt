Implement the function `int64_t bubble_sort(int64_t *a, int64_t n)`.

Target: AArch64 (ARMv8-A), Linux AAPCS64. Integer/pointer arguments in x0-x7; 64-bit result in x0. Callee-saved: x19-x28, x29 (frame pointer) and d8-d15 (restore them if you use them); x9-x15 are free scratch registers. sp must stay 16-byte aligned and be back to its entry value when you return with ret (return address in x30).

Output format: raw AArch64 machine code, which you encode yourself: there is no assembler and no encoder, and your bytes run exactly as you write them. Write one instruction per line as its 32-bit instruction word in hexadecimal, exactly 8 hex digits (an optional 0x prefix is allowed), e.g. `8b010000` is `add x0, x0, x1` and `d65f03c0` is `ret`. The words are stored little-endian, one after another: the first line is the entry point at byte offset 0, the next at offset 4, and so on. There are no labels or symbols: every branch and PC-relative field (b, b.cond, bl, cbz, cbnz, tbz, tbnz, adr) holds the byte offset from the address of that instruction itself, divided by 4 where the encoding says so, which you compute. You may end a line with a comment starting with `//` or `;` (e.g. `8b010000 // add x0, x0, x1`); comments and blank lines are ignored. No directives, no data words, no calls to other functions. No Markdown fences, no prose before or after the code. Instruction set: ARMv8.0-A with floating point and Advanced SIMD (NEON). Not supported (rejected): CRC32, LSE atomics, dot product, half-precision, crypto (AES/SHA/PMULL) and SVE.

Specification: a points to n signed 64-bit integers, n >= 0 (n <= 64). Sort the array in place in ascending order (signed comparison) using bubble sort, and return 0. Write nothing outside a[0..n-1].
