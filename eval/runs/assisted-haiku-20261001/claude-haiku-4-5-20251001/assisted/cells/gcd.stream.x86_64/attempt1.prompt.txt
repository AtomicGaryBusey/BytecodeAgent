Implement the function `int64_t gcd(int64_t a, int64_t b)`.

Target: x86-64, Linux System V ABI. Integer/pointer arguments in rdi, rsi, rdx, rcx, r8, r9; 64-bit result in rax. Callee-saved: rbx, rbp, r12, r13, r14, r15 (restore them if you use them); all other registers may be clobbered. rsp is 16-byte aligned before the call, so it is 8 mod 16 at entry; it must be back to its entry value when you return with ret. Never write to the caller's frame (at or above the return address).

Output format: GNU assembler syntax, Intel flavour without register prefixes (as with `.intel_syntax noprefix`), e.g. `mov rax, qword ptr [rdi + rcx*8]`. Output ONLY the function's instructions and labels, one per line, starting with the label `gcd:` (the entry point). Labels are `name:` (letters, digits, _ and ., e.g. `.Lloop:`); every branch target must be a label, never a number. Comments start with `#`; do not use `;`. No directives of any kind (no .section/.align/.byte/.quad/.p2align), no data, no calls to other functions. Each line under 120 characters. No Markdown fences, no prose before or after the code.

Specification: Return the greatest common divisor of a and b, which are both non-negative (0 <= a, b <= INT64_MAX). gcd(x, 0) = gcd(0, x) = x; gcd(0, 0) = 0. Use Euclid's algorithm.

Notes (to help you avoid common mistakes):
x86-64 reminders: rip-relative addressing takes no index register (`[rip + sym + rcx]` is invalid): load the address with `lea` first, then index from that register. To zero a register use `xor eax, eax` (writing a 32-bit register clears the upper half); `xor rax, 0` changes nothing. `imul` has the forms `imul r, r/m` and `imul r, r/m, imm` (no three-register form). Shifts by a variable count take the count in `cl`. `div`/`idiv` divide rdx:rax: clear rdx (`xor edx, edx`) before an unsigned `div`, sign-extend with `cqo` before `idiv`.
Output discipline: answer with the code only, exactly in the output format above: no plan, no explanation, no Markdown fences, no tool-call or XML markup before, inside or after it.
