Write the complete program `rpn`: a static Linux executable for AArch64 (ARMv8-A, little-endian), written in assembly. There is no C library, no C runtime and no helper code: you write the entry point `_start`, every function, every table and string, and make the system calls yourself.

Entry state (as the Linux kernel sets it up): execution starts at the label `_start`. sp is 16-byte aligned and points at argc = 0, followed by the NULL terminators of an empty argv, an empty envp and an empty auxiliary vector: the program gets no arguments. Every other general-purpose register (x0-x30) is zero; x30 is not a return address, so `_start` must never return with `ret`; the program ends only through the exit system call.

System calls: the `svc #0` instruction, with the system call number in x8 and the arguments in x0, x1, x2; the result comes back in x0. Every other register is preserved. Exactly these four are available:
- read = 63: read(fd = 0, buf, count) reads up to count bytes of standard input into buf; returns the number of bytes read, 0 at end of input.
- write = 64: write(fd, buf, count) with fd 1 (standard output) or 2 (standard error); returns count.
- exit = 93: exit(status) ends the program; the exit status is the low 8 bits of status.
- exit_group = 94: the same as exit.
Any other system call number or file descriptor stops the program with an error, and so does a buffer that is not entirely inside the program's memory.

Memory: the program's own sections plus a stack of 1 MiB below the entry sp. There is no heap (no brk, no mmap, no malloc): put working storage in `.bss` (zero-initialised), at most 1 MiB in total, or on the stack. Code is not writable. Any access outside these areas stops the program. Each test run may execute at most 50,000,000 instructions.

Specification: Task `rpn`: evaluate one Reverse Polish Notation expression per input line and print one result line per input
line.

Lines: a line is a (possibly empty) sequence of bytes terminated by a newline 0x0A; if the input does not end
with a newline, the bytes after the last newline form one more, final line. Empty input has no lines (prints
nothing), and the empty remainder after a final newline is not a line.

Tokens: the separators are space 0x20 and tab 0x09 only; a token is a maximal run of other bytes. Any number of
separators may appear before, between and after tokens. A token is exactly one of:
- an integer literal: an optional `-` followed by 1 to 18 decimal digits `0`-`9` (leading zeros allowed, `-0`
  is 0). A literal with 19 or more digits is invalid;
- an operator: exactly one of `+` `-` `*` `/` `%` (a lone `-` is the subtraction operator);
- anything else (for example `1a`, `+5`, `--3`, `1.5`, `x`, or a token containing 0x0D or any other byte) is
  invalid.

Evaluation uses a stack of signed 64-bit integers, empty at the start of each line. Process tokens left to right:
a literal is pushed; an operator pops b (top) then a, and pushes `a op b`. `+`, `-`, `*` wrap modulo 2^64 (two's
complement). `/` is division truncated toward zero; `%` is the remainder with the sign of a (a == (a/b)*b +
a%b), as in C. A line is an ERROR if: it contains an invalid token; an operator finds fewer than two values on
the stack; `/` or `%` has b == 0; `/` or `%` has a == -9223372036854775808 and b == -1; or, after the last token,
the stack does not hold exactly one value (this includes a line with no tokens, e.g. an empty line).

Output per line: if it is not an error, the single remaining value in decimal (a `-` sign if negative, no `+`,
no leading zeros; -9223372036854775808 must print correctly) followed by a newline; if it is an error, exactly
`error\n`. After an error the rest of that line is ignored and evaluation continues with the next line.

Example: input `3 4 +\n-7 2 /\n1 +\n\n5 1 2 + 4 * + 3 -` prints `7\n-3\nerror\nerror\n14\n`.

Limits: the input is at most 65536 bytes; a line is at most 1000 bytes. Exit status 0.

- Finish with `exit` (or `exit_group`) and the exit status this task gives. The program must not run off the end
