Implement the function `uint64_t isqrt(uint64_t n)`.

Target: AArch64 (ARMv8-A), Linux AAPCS64. Integer/pointer arguments in x0-x7; 64-bit result in x0. Callee-saved: x19-x28, x29 (frame pointer) and d8-d15 (restore them if you use them); x9-x15 are free scratch registers. sp must stay 16-byte aligned and be back to its entry value when you return with ret (return address in x30). More ABI facts: arguments beyond the eighth are passed on the stack (the 9th at [sp] at entry). A call (bl/blr) overwrites x30, so save x30 (e.g. stp x29, x30, [sp, #-16]!) before calling and restore it before ret. A call clobbers the caller-saved registers x0-x18, x30, v0-v7 and v16-v31 (and the upper halves of v8-v15) and the flags, so keep values that must survive a call in callee-saved registers x19-x28 (saved/restored by you) or in your own stack frame. sp must be 16-byte aligned at every call (and whenever it is used as a base register). Anything below sp may be overwritten by a callee.

Output format: QBE intermediate language (the IL of the QBE compiler backend, c9x.me/compile). Write exactly one function, `export function l $isqrt(...)`, taking every argument as `l` (64-bit; pointers are `l` too) and returning `l`. QBE will compile it for the target above, so you do not handle registers or the ABI yourself. Remember: every block starts with an `@label`; temporaries are `%name`; comparisons such as `csltl`/`ceql` produce a `w` value; `jnz` tests a `w`; loads/stores are `loadl`/`storel`. No data definitions, no calls, no other functions. Output only the QBE code: no Markdown fences, no prose.

Specification: Return floor(sqrt(n)) for an unsigned 64-bit n (any value from 0 to 2^64 - 1, e.g. isqrt(2^64 - 1) = 4294967295), i.e. the largest r with r*r <= n. Use integer arithmetic only (binary search or Newton's method; no floating point). Beware of overflow: r*r and intermediate sums can exceed 64 bits near the top of the range, and n is unsigned.

Notes (to help you avoid common mistakes):
QBE cheat sheet (every name below is valid QBE; anything else is not):
- Function: `export function l $name(l %a, l %b) {` ... `}`; every parameter and every result has a class:
  `l` (64-bit), `w` (32-bit). Blocks start with `@label` on its own line (no colon); every block ends with
  `jmp @x`, `jnz %c, @yes, @no` or `ret %v`.
- Instructions: `%t =l op args` (the class after `=` is required). Integer literals are decimal only
  (no 0x...): write 255, not 0xff; negative numbers like -1 are fine.
- Arithmetic (class l or w; both operands the same class): add sub mul div rem udiv urem neg and or xor
  sar shr shl. Copy a value or constant: `%x =l copy 0`.
- Comparisons give a w: c + eq/ne/slt/sle/sgt/sge/ult/ule/ugt/uge + operand class, e.g. `%c =w csltl %a, %b`
  (compare two l values), `ceqw` (two w values). There is no select instruction: branch with jnz.
- Memory: loadl / loadw / loadsw / loaduw / loadsh / loaduh / loadsb / loadub (`%v =l loadl %p`,
  `%b =l loadub %p` zero-extends a byte to l); storel / storew / storeh / storeb (`storel %v, %p`).
  Addresses are l values: `%p =l add %base, %off`.
- Widening a w to l: extsw (signed) / extuw (unsigned); also extsh extuh extsb extub. A function returning
  l must `ret` an l.
- You may assign the same temporary again (QBE builds SSA form itself), so loops need no phi:
  `%i =l add %i, 1` is fine. If you do use phi, `%x =l phi @a %v1, @b %v2` must name every predecessor
  block of that block.
Example:
export function l $sum(l %p, l %n) {
@start
	%s =l copy 0
	%i =l copy 0
@loop
	%more =w csltl %i, %n
	jnz %more, @body, @done
@body
	%off =l mul %i, 8
	%a =l add %p, %off
	%v =l loadl %a
	%s =l add %s, %v
	%i =l add %i, 1
	jmp @loop
@done
	ret %s
}
