Implement the function `int64_t qsort_pairs(int64_t *a, int64_t n)`.

Target: x86-64, Linux System V ABI. Integer/pointer arguments in rdi, rsi, rdx, rcx, r8, r9; 64-bit result in rax. Callee-saved: rbx, rbp, r12, r13, r14, r15 (restore them if you use them); all other registers may be clobbered. rsp is 16-byte aligned before the call, so it is 8 mod 16 at entry; it must be back to its entry value when you return with ret. Never write to the caller's frame (at or above the return address). More ABI facts: arguments beyond the sixth are passed on the stack; at entry the return address is at [rsp], the 7th argument at [rsp+8], the 8th at [rsp+16]. A call clobbers the caller-saved registers rax, rcx, rdx, rsi, rdi, r8-r11, all xmm registers and the flags, so keep values that must survive a call in callee-saved registers (saved/restored by you) or in your own stack frame. rsp must be 16-byte aligned at every call instruction (at entry rsp is 8 mod 16, so an odd number of 8-byte pushes, or `sub rsp, 8` plus any multiple of 16, re-aligns it). Anything below rsp may be overwritten by a callee. The direction flag must be clear at calls and on return.

Output format: QBE intermediate language (the IL of the QBE compiler backend, c9x.me/compile). Write exactly one function, `export function l $qsort_pairs(...)`, taking every argument as `l` (64-bit; pointers are `l` too) and returning `l`. QBE will compile it for the target above, so you do not handle registers or the ABI yourself. Remember: every block starts with an `@label`; temporaries are `%name`; comparisons such as `csltl`/`ceql` produce a `w` value; `jnz` tests a `w`; loads/stores are `loadl`/`storel`. No data definitions and no other functions; the only calls are to $qsort_pairs itself. Output only the QBE code: no Markdown fences, no prose. Call the function itself with `%r =l call $qsort_pairs(l %p, l %m)`.

Specification: a points to n records of two signed 64-bit integers each: record i is (key, value) = (a[2*i], a[2*i+1]), 0 <= n <= 150. Sort the records in place into ascending order by key, and by value among equal keys (signed comparisons; records with equal key and value are identical, so the result is unique), and return 0. The input may be sorted, reverse sorted, all equal, or contain INT64_MIN/INT64_MAX keys and values. The implementation MUST be a recursive quicksort: partition the records around a pivot record, then sort the parts with real call instructions to qsort_pairs's own entry point, passing a pointer to the first record of the part and its number of records (you may loop on one part and recurse on the other; the machine code is checked for a call to its own entry). Every recursive call is a normal ABI call and is checked as one: the stack must be 16-byte aligned at each call, and any callee-saved register you use must be saved and restored. Read and write only a[0..2n-1] (both are checked).
