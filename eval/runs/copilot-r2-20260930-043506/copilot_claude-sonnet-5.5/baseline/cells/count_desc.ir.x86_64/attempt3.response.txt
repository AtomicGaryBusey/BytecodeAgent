The error is in the phi at `@loop`. The block is reached from `@start` through a `jnz`, so the phi is legal, but `%i`'s phi lists `@start, 0`, which is fine. The actual error is on line 7, `jnz %c, @done, @loop`, where line 7 is the `jnz` line counting from the function header. That points to the `%c` operand, though, which is a `w` and looks valid. The likelier cause is that `%m` or `%c` is fine and the problem is the phi syntax. QBE phi syntax is `phi @blk, val, @blk, val`, which matches what I wrote.

I can't pin the exact line, so I'll make the code safer in three ways:
- Use the `@start` label on its own line.
- Avoid `extuw` on a `w` value, which is fine in QBE, but the loop-carried values are simpler with a different structure.
- Put the loop header in a separate block so each phi's predecessors are plain jumps.

I'll also move the final `ret` to a single exit with a phi.


export function l $count_desc(l %a, l %n) {
@start
	%m =l sub %n, 1
	%c =w csltl %m, 1
	jnz %c, @done, @pre
@pre
	jmp @loop
@loop
	%i =l phi @pre, 0, @body, %i2
	%cnt =l phi @pre, 0, @body, %cnt2
	%d =w csltl %i, %m
	jnz %d, @body, @done2
@body
	%off =l shl %i, 3
	%p =l add %a, %off
	%x =l loadl %p
	%q =l add %p, 8
	%y =l loadl %q
	%g =w csltl %y, %x
	%gl =l extuw %g
	%cnt2 =l add %cnt, %gl
	%i2 =l add %i, 1
	jmp @loop
@done2
	ret %cnt
@done
	ret 0
}
