The cause is that the tool likely encodes `test r9, r9` correctly, so the flags are not the problem. The real problem is that rdx is clobbered by `mul`/`idiv`, which the code doesn't use, so that is not it either.

The actual culprit is `imul`, which doesn't touch rdx. The stack pointer is passed in rdx, but the arguments are rdi=code, rsi=len, rdx=stack, rcx=cap, so the register mapping is right. The failing address is 0x10016f, which is code, so the `je` must have been mis-encoded or the jump did not take effect.

This separates the load from the branch and doesn't rely on the `xor` followed by a `test`. The clear loop uses rcx as the cap, which is preserved.
