Register plan:
- rdi = code, rsi = len, rdx = stack base, rcx = cap
- r8 = pc, r9 = sp (number of entries)
- rax, r10, r11 are scratch

Zeroing the stack up front is safe because the buffer is checked only at return. Then run the interpreter. At the end, the entries stack[0..d-1] are already in place and the rest is zero.

Zeroing: r10 = 0, and a loop stores 0 to stack[r10] while r10 < cap.

Main loop: if pc >= len, go to done. Otherwise load rax = code[pc] and dispatch through a compare chain.

Stack is indexed by r9. Top is at [rdx + r9*8 - 8].

- PUSH: r10 = code[pc+1]; stack[r9] = r10; r9++; pc += 2.
- ADD, SUB, MUL: r10 = top; r9--; the new top is a, so `op [rdx+r9*8-8], r10`. For MUL, load rax = a, imul rax, r10, then store it back.
- DUP: r10 = top; stack[r9] = r10; r9++.
- SWAP: r10 = top, r11 = below; swap their stores.
- DROP: r9--.
- OVER: r10 = [rdx+r9*8-16]; stack[r9] = r10; r9++.
- LT: r10 = b; r9--; r11 = a; cmp r11, r10; setl al; movzx eax, al; store to the new top.
- JZ: r9--; r10 = stack[r9]; r11 = code[pc+1]; if r10 == 0 then pc = r11, else pc += 2.
- JMP: pc = code[pc+1].

The dispatch loads rax = code[pc], so the MUL and LT handlers must not depend on rax holding the opcode after dispatch. Both use rax only after the compare chain, so this is fine.

Done: if r9 == 0 return 0, otherwise rax = stack[r9-1].

Because DROP and JZ leave stale values above the top, the stack must be re-zeroed above d at the end. The final cleanup is a loop from r10 = r9 while r10 < cap that stores 0. That makes the initial zeroing unnecessary, since only the final state matters. The initial contents are garbage but only entries below sp are ever read, and those are written first. So I do the cleanup at the end only.

The return value is loaded before the cleanup, since the cleanup only touches slots at or above d.
