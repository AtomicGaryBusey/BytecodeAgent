The function is called shift_sat but the spec is just: left = (x << n) with n >= 64 giving 0, right = (x >> n) with n >= 64 behaving as a shift by 63. The x86 shift instructions mask the count to 6 bits, so both cases need explicit handling.

Plan:
- rcx = n; rax = x; rdx = x (copy).
- `shl rax, cl` uses cl mod 64. Then if n >= 64, set rax to 0 with a cmov.
- For the right shift: compute the count as min(n, 63). Do `mov r8d, 63; cmp rsi, 63; cmova rcx, r8` after saving the left shift, then `sar rdx, cl`.

Order of operations:
1. mov rcx, rsi
2. mov rax, rdi
3. shl rax, cl
4. xor r9d, r9d
5. cmp rsi, 64
6. cmovae rax, r9 (unsigned compare; n is non-negative)
7. mov edx, 63
8. cmp rsi, 63
9. cmova rcx, rdx (rcx = 63 if n > 63)
10. mov rdx, rdi
11. sar rdx, cl
12. add rax, rdx
13. ret

Step 9 uses rdx as a temporary, and step 10 overwrites it afterward, which is fine. Step 8's cmp is not disturbed by step 7's mov, since mov does not affect flags anyway.
