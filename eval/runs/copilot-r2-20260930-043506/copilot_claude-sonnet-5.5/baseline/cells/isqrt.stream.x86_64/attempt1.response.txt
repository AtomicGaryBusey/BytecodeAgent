Use the classic bitwise digit-by-digit method, which never overflows.

Algorithm:
- res = 0
- bit = 1<<62
- while bit > n: bit >>= 2
- while bit != 0:
  - if n >= res + bit: n -= res + bit; res = (res >> 1) + bit
  - else: res >>= 1
  - bit >>= 2

`res + bit` stays below 2^64 because res < 2^32 and bit ≤ 2^62. For n = 0 the first loop shifts bit down to 0 and terminates, since bit > 0 fails once bit is 0. The result is 0.

```
isqrt:
    xor eax, eax
    mov rcx, 0x4000000000000000
.Lshrink:
    cmp rcx, rdi
    jbe .Lmain
    shr rcx, 2
    jmp .Lshrink
.Lmain:
    test rcx, rcx
    jz .Ldone
    lea rdx, [rax + rcx]
    cmp rdi, rdx
    jb .Lless
    sub rdi, rdx
    shr rax, 1
    add rax, rcx
    shr rcx, 2
    jmp .Lmain
.Lless:
    shr rax, 1
    shr rcx, 2
    jmp .Lmain
.Ldone:
    ret
```

Check on the shrink loop: with n=0 and rcx=0x4000..., `cmp rcx, rdi` gives rcx > 0, so `jbe` is not taken and it shifts. Eventually rcx becomes 0, and `cmp 0, 0` is `jbe` taken, going to .Lmain, where the zero test ends it. This is correct.
