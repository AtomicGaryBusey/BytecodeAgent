Use the bitwise digit-by-digit method, which avoids overflow.

```
res = 0; bit = 1<<62
while bit > n: bit >>= 2      (unsigned compare)
while bit != 0:
  if n >= res + bit: n -= res+bit; res = (res>>1) + bit
  else res >>= 1
  bit >>= 2
```

`res + bit` is at most about 2^63 or a bit more, so it fits in 64 bits. The compare must be unsigned, so use `cultl`/`cugel`. With bit = 2^62 and res = 0, `res + bit` is 2^62. Later res is below 2^32, so there is no overflow.

Loop structure:
- @start: bit=4611686018427387904, jump to @l1.
- @l1: c = cultl n, bit (n < bit); if c, go to @shr, else go to @l2.
- @shr: bit >>= 2, jump to @l1. If n = 0, bit shifts down to 0 and the loop terminates, because 0 < 0 is false and we fall through to @l2, where bit = 0 exits.
- QBE has no mutable SSA variables, so use phi nodes.

```
export function l $isqrt(l %n) {
@start
	jmp @l1
@l1
	%bit =l phi @start 4611686018427387904, @shr %bit2
	%c =w cultl %n, %bit
	jnz %c, @shr, @l2
@shr
	%bit2 =l shr %bit, 2
	jmp @l1
@l2
	%b =l phi @l1 %bit, @next %bn
	%r =l phi @l1 0, @next %rn
	%m =l phi @l1 %n, @next %mn
	%z =w ceql %b, 0
	jnz %z, @end, @body
@body
	%s =l add %r, %b
	%ge =w cugel %m, %s
	%r1 =l shr %r, 1
	jnz %ge, @yes, @no
@yes
	%m2 =l sub %m, %s
	%r2 =l add %r1, %b
	jmp @next
@no
	jmp @next
@next
	%mn =l phi @yes %m2, @no %m
	%rn =l phi @yes %r2, @no %r1
	%bn =l shr %b, 2
	jmp @l2
@end
	ret %r
}
```
