The bug is the third argument. `t` is the third argument, so it arrives in `rdx`. The previous code used `rdx` correctly as `t`, but `"src":["rdx"]` with `xor eax, eax` looks fine, and the result was garbage, so the likely cause is how the encoder handled the instructions. I suspect `xor eax, imm 0` was encoded oddly, so I switched to register-register `xor`. I also replaced `seta`/`movzx` with `sbb`, and the loop now uses a pointer and a counter.

The plan is to compute `t < a[i]` with `cmp rdx, [a+i*8]`. That sets CF when `t < a[i]` unsigned. Then `adc rax, 0` adds the carry to the count.

```
xor eax, eax
xor ecx, ecx
loop:
  cmp rcx, rsi
  jge done
  cmp rdx, [rdi+rcx*8]
  adc rax, 0
  inc rcx
  jmp loop
done:
  ret
```

`cmp rcx, rsi` is a signed compare, which is fine because `n` is between 0 and 40.
