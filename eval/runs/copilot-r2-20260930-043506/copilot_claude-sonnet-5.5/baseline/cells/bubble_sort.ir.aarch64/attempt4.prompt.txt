The likely problem is the phi syntax. In QBE, phi arguments are written `@label value` with no comma between them, as in `phi @start %m0, @onext %m1`. My earlier version put a comma after each label, which QBE rejects.

The `@inner` phi also has a bug. Its predecessors are `@outer` and `@inc`, but the `@outer` phi's second argument comes from `@onext`, which is only reached from `@inner`. That is fine. But `@inc` is reached from both `@ibody` and `@swap`, and `%i2` is defined in `@inc`, which is fine too.

Every block that is a phi predecessor must actually jump to the block containing the phi. `@outer` jumps to `@inner`, so that is correct.

When n = 0, `%m0` is -1, so `%m > 0` is false and the function goes straight to `@done`. That is fine.

I fixed the phi syntax in both places.

@start
	%m0 =l sub %n, 1
	jmp @outer
@outer

	jnz %c, @inner, @done
@inner
