Constants as signed decimals:
- P1 = 0x9E3779B185EBCA87 = -7046029288634856825
- P2 = 0xC2B2AE3D27D4EB4F = -4417276706812531889
- P3 = 0x165667B19E3779F9 = 1609587929392839161
- P4 = 0x85EBCA77C2B2AE63 = -8796714831421723037
- P5 = 0x27D4EB2F165667C5 = 2870177450012600261

I'll trust QBE to accept these decimals as 64-bit constants.

The structure is: a stripe loop while at least 32 bytes remain, then an 8-byte loop, an optional 4-byte step, a byte loop, and the final avalanche. Pointer `%q` and remaining count `%r` are tracked through phis.

The round is inlined as `m = x*P2; a = acc+m; rot = (a shl 31) or (a shr 33); res = rot*P1`.

The merge step is `h = (h ^ round(0,v)) * P1 + P4`. Here round(0,v) = rotl(v*P2, 31)*P1.

Blocks:
- **@start:** if n >= 32, jump to @big, otherwise to @small.
- **@small:** h0 = seed + P5, q = p, r = n, then jump to @tail.
- **@big:** initialise v1–v4 and go to @loop. The loop phis carry v1–v4, q and r. @loop checks r >= 32. If so it runs @body and jumps back, otherwise it goes to @fin.
- **@fin:** compute h from the rotated accumulators and the four merges, then jump to @tail.
- **@tail:** phis for h, q, r from both predecessors (@small and @fin). Add n to h once here, in a separate block @t0 that both paths jump to, using phi inputs `%hs` and `%hb`.
- **@l8:** phi for h, q, r. If r >= 8, do the 8-byte step, else go to @c4.
- **@c4:** if r >= 4, do the 4-byte step; the phi at @b merges the two cases.
- **@b:** byte loop, if r > 0.
- **@end:** avalanche.
