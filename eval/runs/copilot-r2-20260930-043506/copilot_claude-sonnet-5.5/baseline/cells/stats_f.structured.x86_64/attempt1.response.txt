Register plan, with all of these callee-saved:
- rbx = a pointer
- r12 = n
- r13 = f
- r14 = out
- r15 = index i
- rbp = odd count

min, max and sum live on the stack. The six pushes plus the return address make the entry rsp 8 mod 16 after 6 pushes → 8+48 = 56, which is 8 mod 16. Subtracting 40 gives rsp 0 mod 16 and leaves room for 5 slots; I use 3 (min at [rsp], max at [rsp+8], sum at [rsp+16]).

Entry: the six pushes shift rsp by 48, so rsp ≡ 8+48 = 56 ≡ 8 mod 16. `sub rsp, 24` gives 32 ≡ 0, which is aligned and enough for the 3 slots.

Loop structure:
- Initialise i=0, odd=0, sum=0, min=INT64_MAX and max=INT64_MIN. To avoid 64-bit immediates, I handle the first element separately: after the first call, set min=max=sum=y. The simpler route is a flag, so I use the first-iteration approach with i==0 check.
- Per iteration: load a[i] into rdi, call f, then test al bit 0 and add it to rbp (`mov rcx, rax; and ecx, 1; add rbp, rcx`).
- If i == 0, store min, max and sum from rax and jump to the next step.
- Otherwise: cmp rax with [rsp]; if not less, skip the min update. cmp rax with [rsp+8]; if not greater, skip the max update. Then add rax to [rsp+16].
- Increment i and loop while i < n.
- At the end, copy min, max and sum to out and return rbp in rax.
