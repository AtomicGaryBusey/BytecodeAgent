Design: Lomuto partition with the last record as pivot. Recurse on the left part, loop on the right part. Lomuto with all-equal input degrades to O(n^2), which is fine for n ≤ 150. Recursion depth is also fine, since the left part is recursed on and the right part is looped on. Worst-case depth is at most 150 frames, which is fine.

Algorithm, with a pointer and a count:
- while n >= 2:
  - pivot key pk = a[2(n-1)], pivot value pv = a[2(n-1)+1]
  - i = 0
  - for j in 0..n-1 (excluding the last): if (key_j, val_j) < (pk, pv), swap record j with record i and increment i
  - swap record i with record n-1; the pivot is now at index i
  - recurse on (a, i)
  - a = a + 16*(i+1), n = n-i-1
- return 0

The less-than test is (kj < pk) or (kj == pk and vj < pv), computed as `csltl`, `ceql`, `csltl`, then `and`, then `or`.

The pivot values are kept in temporaries across the call, but they are recomputed on each loop iteration, so no state needs to survive the call other than a and n. QBE allocates registers across calls itself, so I store nothing manually.
