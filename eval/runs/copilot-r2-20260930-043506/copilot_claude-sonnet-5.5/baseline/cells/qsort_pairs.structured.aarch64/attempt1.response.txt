Design: qsort_pairs(a, n). If n < 2, return 0. Otherwise use a Lomuto partition with the last record as pivot, then recurse on both parts.

Registers: x19 = a, x20 = n, x21 = pivot key, x22 = pivot value, x23 = i (the store index), x24 = j.

Partition loop, for j in 0..n-2:
- Load the record (k, v) at a + 16j.
- It is less than the pivot if k < pk, or k == pk and v < pv.
- Compare k with pk. If lt, take it. If gt, skip. If eq, compare v with pv; if lt, take it.
- Taking it means swapping records i and j, then i++.

After the loop, swap record i with record n-1 (the pivot). Then recurse on (a, i) and on (a + 16(i+1), n-i-1).

Swap i and j: x9 = a + 16i, x10 = a + 16j. Load x11, x12 from [x9] and x13, x14 from [x10], then store them crosswise. The same routine works for the final swap with j = n-1.

The pivot values are held in registers, so swapping the last record is safe. Within the loop the pivot record is never touched, because j < n-1.

The frame is 64 bytes, holding x29, x30 and x19-x24 (stp pairs at offsets 0, 16, 32, 48). That is 8 registers: x29/x30, x19/x20, x21/x22, x23/x24, so it needs 64 bytes.

Loop code:
```
lsl x9,x24,#4; add x9,x19,x9; ldp x11,x12,[x9]
cmp x11,x21; b.lt take; b.gt skip; cmp x12,x22; b.ge skip
take: swap with i; add x23,x23,1
skip: add x24,x24,1; cmp x24,x20-1 ...
```
The loop bound is n-1, held in x25. So I save x25 too, and use x25/x26 as a pair, making the frame 80 bytes.

Final swap: j = n-1, then reuse the swap code by branching. I'll just inline it a second time.
