Plan: zero r[0..na+nb-1], then for each i in a, multiply by b and accumulate into r[i..], with the carry stored at r[i+nb]. Finally scan from the top for the significant length.

Registers: rdi=a, rsi=na, rdx=b, rcx=nb, r8=r. Since mul clobbers rdx, move b to r9 first.

- r9 = b
- r10 = na+nb (total)
- zero loop: for k in 0..total, r[k]=0, using rax as the zero and r11 as the counter.
- outer loop over i (rbx, callee-saved, so push it).
  - r11 = a[i]; if 0, skip (r[i+nb] is already 0 or correctly holds its value, since we only add; skipping is fine).
  - j=0 (rsi is free to reuse as j after na is saved), carry in rbp (push it too).
  - inner: rax = b[j]; mul r11; add rax, carry; adc rdx, 0; add r[i+j], rax; adc rdx, 0; carry = rdx; j++.
  - After the inner loop, r[i+nb] += carry. That slot has not been written by this row, and earlier rows only reached up to i-1+nb, so it is 0; a plain store is fine.
  - The i+j index needs a register: r12 = i+j. Instead use lea rax, [r8+rbx*8] as the row base (r13), then index by j.
- Skip case: when a[i]=0, r[i+nb] stays 0 from the zeroing, which is correct.
- Final: rax = total; loop while rax>0 and r[rax-1]==0, decrementing.

Register assignment: rbx=i, rbp=carry, r12=row base, r13=na, rsi=j, r11=a[i], rcx=nb, r10=total. Pushing 3 registers gives an odd count, but no calls are made so alignment does not matter.

Edge case: nb=0 gives an empty inner loop, and the store to r[i+0] would write out of range. It would also write when na>0, so handle it by jumping to the finish if nb==0 (total=na, all zeros, and the scan returns 0). Similarly if na==0, the outer loop does not run.
