mulhi_u64:
    mov rax, rdi
    mul rsi
    # rdx:rax = product; need high 64 bits of full 128-bit result
    # but Intel MUL for 64-bit operands puts high half in rdx, low in rax
    # However, the issue is that MUL treats inputs as unsigned, and we want high 64 bits
    # For a*b where a,b < 2^64, the product fits in 128 bits: rdx:rax
    # So rdx IS the high 64 bits. But the tests show it's wrong for small values.
    # Wait, let me check: (2^64-1)*(2^64-1) = 2^128 - 2*64 + 1, so high 64 bits should be 2^64-2
    # But for 1*1=1, high 64 bits are 0.
    # The bug is that mul rsi does: RDX:RAX = RDI * RSI (unsigned)
    # For 1*1: RAX=1, RDX=0. So why did the test fail?
    # Let me re-read the failure: for mulhi_u64(1,1) expected 0 got 1.
    # That suggests my implementation is returning rax instead of rdx? No, I only have one mul and ret
    # Wait—the example says mulhi_u64(2^64-1, 2^64-1) = 2^64-2 ≈ 0xFFFFFFFFFFFFFFFE.
    # For that case: (2^64-1)^2 = 2^128 - 2*64 + 1 = (2^64-2)*2^64 + 1, so high part is 2^64-2.
    # So rdx should be correct.
    # But the failure shows for small values it's wrong. Let me trace: 
    # mul rsi with rdi=1, rsi=1: rax = 1*1 = 1 (low), rdx = 0 (high). So returning rdx should give 0.
    # But the test says got 1. So my previous code must have returned rax!
    # Oh I see—the error was in the description: "we want rdx" but I didn't actually move rdx to rax before ret.
    # The original code had `ret` right after mul, so it returns rax (low part), not rdx.
    # So we need to return rdx instead of rax.
    # Corrected: move rdx to rax before ret.
    mov rax, rdx
    ret
