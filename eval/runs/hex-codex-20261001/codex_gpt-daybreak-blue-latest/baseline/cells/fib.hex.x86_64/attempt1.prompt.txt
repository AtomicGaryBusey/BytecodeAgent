Implement the function `int64_t fib(int64_t n)`.

Target: x86-64, Linux System V ABI. Integer/pointer arguments in rdi, rsi, rdx, rcx, r8, r9; 64-bit result in rax. Callee-saved: rbx, rbp, r12, r13, r14, r15 (restore them if you use them); all other registers may be clobbered. rsp is 16-byte aligned before the call, so it is 8 mod 16 at entry; it must be back to its entry value when you return with ret. Never write to the caller's frame (at or above the return address).

Output format: raw x86-64 machine code, which you encode yourself: there is no assembler and no encoder, and your bytes run exactly as you write them. Write one instruction per line as its bytes in memory order, each byte as two hex digits, separated by spaces, e.g. `48 01 f0` is `add rax, rsi` and `c3` is `ret`. The lines are placed one after another: the first line is the entry point at byte offset 0. There are no labels or symbols: every relative branch or call displacement (jmp, jcc, call rel8/rel32) is the signed byte distance from the end of that instruction (the address of the next one) to the target, little-endian, which you compute. You may end a line with a comment starting with `//` or `;` (e.g. `48 01 f0 ; add rax, rsi`); comments and blank lines are ignored. No directives, no data bytes, no calls to other functions. No Markdown fences, no prose before or after the code. Instruction set: x86-64 with SSE up to SSE4.2 (including SSSE3, SSE4.1 and crc32), POPCNT, LZCNT, BMI1/BMI2 (andn, bextr, blsi, blsr, tzcnt, bzhi, mulx, pdep, pext, rorx, sarx, shlx, shrx), MOVBE, AES-NI and PCLMULQDQ. Not supported (rejected): AVX, AVX2, AVX-512, FMA, F16C and every other VEX/EVEX vector instruction, ADX (adcx/adox; use adc) and SHA.

Specification: Return the n-th Fibonacci number with fib(0) = 0, fib(1) = 1, fib(k) = fib(k-1) + fib(k-2), computed iteratively with wrapping 64-bit arithmetic (modulo 2^64). 0 <= n <= 90.
