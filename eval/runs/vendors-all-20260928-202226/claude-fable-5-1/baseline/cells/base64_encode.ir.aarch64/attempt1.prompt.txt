Implement the function `int64_t base64_encode(const uint8_t *src, int64_t n, char *out)`.

Target: AArch64 (ARMv8-A), Linux AAPCS64. Integer/pointer arguments in x0-x7; 64-bit result in x0. Callee-saved: x19-x28, x29 (frame pointer) and d8-d15 (restore them if you use them); x9-x15 are free scratch registers. sp must stay 16-byte aligned and be back to its entry value when you return with ret (return address in x30). More ABI facts: arguments beyond the eighth are passed on the stack (the 9th at [sp] at entry). A call (bl/blr) overwrites x30, so save x30 (e.g. stp x29, x30, [sp, #-16]!) before calling and restore it before ret. A call clobbers the caller-saved registers x0-x18, x30, v0-v7 and v16-v31 (and the upper halves of v8-v15) and the flags, so keep values that must survive a call in callee-saved registers x19-x28 (saved/restored by you) or in your own stack frame. sp must be 16-byte aligned at every call (and whenever it is used as a base register). Anything below sp may be overwritten by a callee.

Output format: QBE intermediate language (the IL of the QBE compiler backend, c9x.me/compile). Write exactly one function, `export function l $base64_encode(...)`, taking every argument as `l` (64-bit; pointers are `l` too) and returning `l`. QBE will compile it for the target above, so you do not handle registers or the ABI yourself. Remember: every block starts with an `@label`; temporaries are `%name`; comparisons such as `csltl`/`ceql` produce a `w` value; `jnz` tests a `w`; loads/stores are `loadl`/`storel`. No data definitions, no calls, no other functions. Output only the QBE code: no Markdown fences, no prose. Load a byte zero-extended with `%b =l loadub %p`; store one with `storeb %c, %p`.

Specification: Encode the n bytes at src (0 <= n <= 200) as standard Base64 (RFC 4648, with '=' padding) into out and return the number of characters written, 4 * ceil(n / 3). Each group of 3 input bytes b0 b1 b2 forms the 24-bit value (b0 << 16) | (b1 << 8) | b2, emitted as four 6-bit indices from the most significant; index v maps to 'A'+v for v < 26, 'a'+(v-26) for v < 52, '0'+(v-52) for v < 62, '+' for 62 and '/' for 63. A final group of 1 byte gives 2 characters then "=="; of 2 bytes, 3 characters then "=". Example: "foobar" -> "Zm9vYmFy", "fo" -> "Zm8=". Do not write a terminating NUL. There is no data section: compute the alphabet mapping with arithmetic/compares. Read only src[0..n-1] (reads are checked: never load past src[n-1], even for a partial final group) and write only out[0..4*ceil(n/3)-1].
